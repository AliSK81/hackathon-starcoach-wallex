# Crypto LLM Trading Systems: NoFx, CloddsBot, Hyper-Alpha-Arena, Nof1 Alpha Arena

**Scope**: how existing open-source LLM crypto traders loop, prompt, validate, gate risk and execute, plus what Nof1 Alpha Arena showed about LLM failure modes. · **Researched**: 2026-10-21
**Repos+commits** (shallow clones, read-only, nothing executed): `NoFxAiOS/nofx@4a5e9ac` (Go, AGPL-3.0, LICENSE verified), `alsk1992/CloddsBot@c930628` (TS, MIT, verified), `HammerGPT/Hyper-Alpha-Arena@9bdf62d` (Python, Apache-2.0, verified). NoFx default `scan_interval_minutes` = 15 (`store/trader.go:29`). Alpha Arena = web sources only (all secondary; see Unverified).

## TL;DR
- The two real closed-loop LLM traders (NoFx, Hyper-Alpha-Arena) run the LLM every **2.5 to 15 min** (HAA `trigger_interval` default 150 s, `models.py:284`; NoFx `ScanInterval` "recommended 15 minutes", `trader/auto_trader.go:147`). Alpha Arena (reconstructed) used 2-3 min. Cadence is itself the main overtrading lever.
- Both force the model to emit **structured JSON with entry, stop, target, confidence and a reasoning string**, and both parse tolerantly. NoFx wraps output in `<reasoning>...</reasoning><decision>```json [...]```</decision>`; HAA demands "ONLY a JSON object" with `decisions[]`.
- **Hard risk lives in code in NoFx** (position-value cap = equity x ratio, max positions, min size, leverage clamp, R:R >= 3 check, margin cap) and is *also* repeated in the prompt. HAA's code-side checks are thin (leverage <= max, 0 < portion <= 1; "keep margin below 70%" is prompt-only). That is the pattern to copy from NoFx, not HAA.
- NoFx falls back to **"wait" when the LLM output has no parseable JSON** (`SafeFallback`, `kernel/engine_analysis.go:327-360`) and enters **safe mode after 3 consecutive AI failures** (no new opens, existing positions kept; `trader/auto_trader_loop.go` ~l.170-190). Good fail-closed behavior; port it.
- NoFx authors added **code-side trade-frequency gates** after replaying 4,154 decision cycles: min hold 90 min, 4 h re-entry cooldown per symbol, noise-close gate (`trader/auto_trader_throttle.go:12-27`). Evidence that prompt text ("avoid overtrading") is insufficient and code gates win.
- CloddsBot is **not** an LLM-in-the-loop crypto trader (its crypto-hft strategies are deterministic orderbook rules for Polymarket 15-min markets; the LLM is a chat agent calling trading tools). Useful only for its risk-engine layout and decision ledger (see file 09).
- Alpha Arena S1 (Oct 18-Nov 3 2025, 6 LLMs, $10k each, Hyperliquid perps, leverage up to 20x): only Qwen3 Max (+22%) and DeepSeek V3.1 (small +) finished positive; GPT-5, Gemini 2.5 Pro, Grok 4, Claude Sonnet 4.5 lost heavily. Reported causes: over-leverage/liquidations, concentrated unhedged longs, high trade count (fee drag), regime blindness. All numbers are from secondary sources and conflict in places.
- For Wallex spot (no shorting, no leverage) the dominant losers become **fee drag + churn + whipsaw stops**, not liquidation. Design for few, larger-edge trades.

## Findings

### 1. NoFxAiOS/nofx @4a5e9ac (Go; Hyperliquid/Binance/etc. perps)
**Loop** (`trader/auto_trader_loop.go: runCycle`, l.19+): per cycle = reload strategy config -> auth check -> stop-pause check -> build context (`buildTradingContext`, l.465) -> save equity snapshot -> `kernel.GetFullDecisionWithStrategy(ctx, mcpClient, engine, "balanced")` -> sort decisions (closes before opens, `sortDecisionsByPriority`) -> filter to strategy universe -> safe-mode filter -> execute each with per-order risk enforcement -> save `DecisionRecord`. First cycle runs immediately; then `time.NewTicker(ScanInterval)` (`auto_trader.go:604-615`). A separate **drawdown monitor goroutine every 1 min** (`auto_trader_risk.go:34-57`) closes a position when price PnL > +5% and giveback from peak >= 40% (`shouldDrawdownClose`, consts at l.12-18).

**Prompt** (`kernel/engine_prompt.go`): system prompt assembled in order: (0) data dictionary/schema `GetSchemaPrompt` (`kernel/schema.go:446`), (1) role ("# You are a professional Hyperliquid USDC multi-asset trading AI"), (2) mode variant, (3) hard constraints (`writeHardConstraints`, l.512) split under headers `## CODE ENFORCED (backend validation, cannot be bypassed)` vs `## AI GUIDED (recommended)`, (4) trading-frequency text ("Excellent traders: 2-4 trades/day ... >2 trades/hour = overtrading ... hold time >= 45-90 minutes"), (5) entry standards, (6) decision process, (7) output format (`writeOutputFormat`, l.609). Position-sizing guidance in prompt: confidence >=85 -> 80-100% of limit; 70-84 -> 50-80%; 60-69 -> 30-50%; "DO NOT just use available_balance". User prompt (`BuildUserPrompt`, l.757): `Time | Period #n | Runtime`, BTC line (price, 1h/4h change, MACD, RSI7), `Account: Equity | Balance (%) | PnL% | Margin% | Positions`, "Recent Completed Trades" (entry/exit/PnL/hold), "Historical Trading Statistics" (profit factor, Sharpe, win/loss, max DD) with a canned `Performance: GOOD/NEEDS IMPROVEMENT/HIGH RISK` hint, current positions, then per-candidate market data (`formatMarketData` l.1055: multi-timeframe series, EMA/MACD/RSI/ATR/BOLL per `IndicatorConfig`), OI/netflow/quant data (`formatQuantData` l.1225).
**Output schema** (`kernel/engine.go:119 Decision`): `symbol, action(open_long|open_short|close_long|close_short|hold|wait), leverage, position_size_usd, stop_loss, take_profit, confidence(0-100), risk_usd, reasoning`. Prompt rule: "all numeric values must be calculated numbers, NOT formulas" (LLM arithmetic is a known failure).
**Validation** (`kernel/engine_analysis.go:283 parseFullDecisionResponse`): extract `<reasoning>` as CoT; extract `<decision>` JSON, normalise full-width/curly punctuation (`fixMissingQuotes`), reject `~` ranges and thousand-separator commas (`validateJSONFormat` l.414), `json.Unmarshal` into `[]Decision`; **no JSON -> synthetic `{Symbol:"ALL",Action:"wait"}`**. Then `validateDecisionForMode` (`kernel/engine_position.go:28+`): action whitelist; for opens: leverage >0 and *clamped* to max (not rejected), size>0, min size (12 USDT, BTC/ETH 60), size <= equity x ratio (+1% tolerance), stop_loss>0, TP>0, long SL<TP / short SL>TP, and **R:R >= 3.0 computed with an assumed entry at 20% of the SL->TP range** (l.~113-139). The entry-price assumption is a heuristic; note LLM-chosen SL/TP are validated for geometry but not against the live mark price in this function (done later: `validateProtectionPrices` in `auto_trader_signal_policy.go:27`: SL on correct side of market price).
**Hard vs prompt rules** (`store/strategy.go:960 RiskControlConfig`, comments are literal): CODE ENFORCED = `MaxPositions` (default 3), `BTCETHMaxPositionValueRatio` (5x equity), `AltcoinMaxPositionValueRatio` (1x), `MaxMarginUsage`, `MinPositionSize` (12). AI GUIDED = `*MaxLeverage`, `MinRiskRewardRatio` (default 3.0), `MinConfidence` (default 78; store clamps to >=50). Enforcement functions: `enforcePositionValueRatio` (caps, does not reject; `auto_trader_risk.go:231`), `enforceMinPositionSize`, `enforceMaxPositions` (l.327/344).
**Throttling by code** (`trader/auto_trader_throttle.go:12-27`, comment: "validated by decision replay (2026-07-26, 4154 cycles, 3-fold robustness)"): `autopilotMinHoldDuration=90m`, `autopilotNoiseCloseHoldDuration=3h`, `autopilotReentryCooldown=4h`, bypass if price PnL <= -3% or >= +8%, noise band -2%..+3%. These apply on the "vergex_signal"/autopilot path; the general path relies on prompt text.
**Execution/leverage**: exchange adapters under `trader/{binance,hyperliquid,okx,bybit,...}`; decisions are `open_long/short` with leverage, orders recorded in `store/order.go`/`position*.go`, fills reconciled (`position_reconcile.go`). `trader/execution/decimal.go` enforces decimal precision for prices/quantities and durable client order IDs.
**Logging**: `store/decision.go:DecisionRecordDB` stores `system_prompt, input_prompt, cot_trace, decision_json, raw_response, candidate_coins, execution_log, ai_request_duration_ms` + account/position snapshots (details in file 09).
**Backtest/paper**: no LLM-in-the-loop backtester found in the Go tree (`grep backtest` hits only `planning/harness`, `planning/market/candles.go`). Authors mention an offline "decision replay" in a code comment but the replay tool was not located (open question).
**Failure modes seen in code comments**: margin-basis drawdown trigger "armed at a +0.5% price wiggle and strangled every winner" at 10x (`auto_trader_risk.go:12-14`) -> switched to price basis; re-entry into just-closed symbol "a consistent loss source" (throttle.go:15-16).
**Measured results**: none published in repo (not found).

### 2. Hyper-Alpha-Arena @9bdf62d (Python/FastAPI; Hyperliquid + Binance perps; Apache-2.0)
**Loop**: APScheduler (`services/scheduler.py`, IntervalTrigger) per account; `Account.trigger_interval` default **150 s** (`database/models.py:284`) plus signal-triggered activations (OI surge, funding spike, breakout; `signal_detection_service.py`). `call_ai_for_decision` (`services/ai_decision_service.py:1948`) fetches news (CoinJournal), loads the bound prompt template, builds context (`_build_prompt_context`, l.602), calls an OpenAI-compatible endpoint with `max_retries = 3` (l.2106), temperature 0.7 for non-reasoning models (l.1798).
**Prompt templates** (`config/prompt_templates.py`): `DEFAULT_PROMPT_TEMPLATE` ("You are a cryptocurrency trading AI.") with sections TRADING ENVIRONMENT, ACCOUNT STATUS (`{available_cash}`, `{total_account_value}`), MARKET PRICES, NEWS, TRIGGER CONTEXT (text: "The trigger is NOT a trade instruction ... A valid trigger may still result in 'hold'"), TRADING RULES ("Keep total margin usage below 70%"), OUTPUT FORMAT. `PRO_PROMPT_TEMPLATE` adds runtime minutes, total return %, holdings, price history, and user-pluggable indicator variables like `{BTC_RSI14_15m}`, `{BTC_MACD_15m}`, `{BTC_BOLL_15m}`, `{BTC_VWAP_15m}`; default exits in prompt: "Long: exit if price drops 5% below entry".
**Output schema** (`OUTPUT_FORMAT_COMPLETE`, ai_decision_service.py:506): `{"decisions":[{operation: buy|sell|hold|close, symbol, target_portion_of_balance 0-1, leverage 1..MAX, max_price (buy), min_price (sell/close), time_in_force Ioc|Gtc|Alo, take_profit_price, stop_loss_price, tp_execution/sl_execution market|limit, reason, trading_strategy}]}` with rules "ONLY a JSON object / NO markdown / NO text outside". `max_price/min_price` act as **slippage guards** (IOC limit at the LLM-supplied bound; if missing, falls back to market price within 1%, `trading_commands.py:710-731`).
**Validation** (`services/trading_commands.py` ~l.630-870): `0 < target_portion <= 1`, `1 <= leverage <= max_leverage` (wallet-configured, default 20), margin = `available_balance * target_portion`. Everything else (margin cap, SL requirement, R:R) is prompt-only. No stop is *required* (stop_loss_price optional) -> a known weakness.
**Execution**: `hyperliquid_trading_client.py` / `binance_trading_client.py`; TP/SL placed as separate trigger orders (`tp_order_id`, `sl_order_id` stored in log).
**Backtest**: (a) `backtest/engine.py ProgramBacktestEngine` for rule-based "Program Trader" with `ExecutionSimulator(slippage_percent=0.05, fee_rate=0.035)` (`backtest/execution_simulator.py:45-46`); (b) `services/prompt_backtest_service.py` re-asks the LLM at stored historical decision points with a modified prompt (parallel, `ThreadPoolExecutor`) -> measures decision change, not PnL; (c) `signal_backtest_service.py` for trigger signals. Paper: Hyperliquid **testnet** (README l.34) and an internal paper account.
**Logging**: `AIDecisionLog` table (`database/models.py:331`): `prompt_snapshot, reasoning_snapshot, decision_snapshot, executed, order_id, hyperliquid_order_id, tp_order_id, sl_order_id, realized_pnl, prompt_template_id, signal_trigger_id`.
**Known gaps** (observed in code): no hash of prompt, no market snapshot stored with the decision, `reason` column is `String(1000)`; DB rows are mutable.
**Results**: none published in repo.

### 3. alsk1992/CloddsBot @c930628 (TS; prediction markets + some crypto futures)
- `src/agents/index.ts:217` `SYSTEM_PROMPT = "You are Clodds, an AI assistant for prediction markets. Claude + Odds."`: a **chat agent with tool-calling**; trade tools (`execute_trade`, `place_order`, `open_position`...) are intercepted by ledger hooks (`src/ledger/hooks.ts:36-50 TRADING_TOOLS`). Not an autonomous periodic decision loop.
- `src/strategies/crypto-hft/{strategies,types,market-scanner}.ts`: four deterministic strategies (Momentum, Reversion, Penny Clip, Expiry Fade) on Polymarket 15-min crypto markets; config has `sizeUsd, minShares ("survive taker fee round-trip"), maxPositionUsd, maxPositions, minTimeLeftSec, forceExitSec, warmupSec`, max orderbook staleness (ms) before skipping entry. No LLM.
- **Risk engine** `src/risk/engine.ts` documents a 10-step pre-trade pipeline: kill switch -> circuit breaker -> max order size -> exposure -> daily loss -> max drawdown -> concentration -> VaR -> volatility regime -> Kelly sizing. Returns `RiskDecision{approved, adjustedSize, reason, checks[]}` with per-check `{name, passed, message}` (good verdict schema). `src/execution/circuit-breaker.ts` defaults: `maxLossUsd 1000, maxLossPct 10, maxConsecutiveLosses 5, maxErrorRate 0.5, minTradesForErrorRate 10, resetTimeoutMs 1h, cooldownMs 5min, maxPositionSize 10000, maxDailyTrades 100`.
- `AUDIT.md` says 25 test files; risk-guards 8/8 pass (self-reported).
- Results: none.

### 4. Nof1 Alpha Arena (web; secondary sources; no official prompt published)
- **Setup** (Season 1): Oct 18 - Nov 3 2025; Qwen3 Max, DeepSeek V3.1, GPT-5, Gemini 2.5 Pro, Claude Sonnet 4.5, Grok 4; $10,000 each; Hyperliquid perps BTC/ETH/SOL/BNB/DOGE/XRP; no human intervention (gncrypto.news; techntrek.is-a.dev).
- **Reconstructed prompt** (community gist https://gist.github.com/namjar/760191f95e8578182d66d9fc88b31b48, explicitly "not official"): decisions every 2-3 min; inputs per coin: price, EMA20, MACD, RSI7/14 (3-min series, oldest->newest), 4h EMA20/50, ATR3/14, volume, OI, funding; account: return %, **Sharpe ratio**, cash, positions with liq price and the model's own prior `exit plan`/confidence. Output: `signal(buy_to_enter|sell_to_enter|hold|close), coin, quantity, leverage 1-20, profit_target, stop_loss, invalidation_condition, confidence 0-1, risk_usd, justification<=500 chars`. Rules: one position per coin, market orders only, ~40% max per position, >=2:1 R:R, liquidation >15% from entry, "prefer hold when no clear edge". Also reproduced in `kojott/LLM-trader-test` (JSON-only signals with `invalidation_condition`; risk 1-2% per trade; Type A/B/C entry tiers).
- **Plan persistence** (Flat Circle blog https://blog.flatcircle.ai/p/ai-trading-arenas): each model first writes a trading plan (target, stop, invalidation) that is fed back into later calls, mitigating non-determinism.
- **Results** (conflicting snapshots): Forklog final: Qwen3 Max $12,231; DeepSeek $10,489; Claude $5,799; Gemini $5,445; Grok $4,208; GPT-5 $4,126. Buildix (secondary, unverified): Qwen +22.3% (43 trades, 30.2% win rate), DeepSeek +4.89%, Claude -30.8%, Grok -45.3%, Gemini -56.7% (**238 trades, $1,331 fees**), GPT-5 -62.7%. iWeaver intermediate snapshot (Oct 22): Claude 20x ETH long liquidated; GPT-5 two margin calls.
- **Reported failure modes**: over-leverage and liquidations; 100% long books without hedge/stop; reactive buy-high/sell-low; flip-flopping stance (Gemini); fee drag >13% of capital for the most active model (Buildix claim); slow regime adaptation; non-determinism (same model, different answer). Qwen: fewer trades, moderate leverage, longer holds; DeepSeek: hedging and vol-based sizing (qualitative).
- Season 1.5 (stocks, 4 arenas): per Flat Circle "all models eventually lost money"; mystery model +12.11% per Buildix (unverified).

## Lessons: what makes LLM crypto traders lose, and the fix
| Failure | Evidence | Guardrail (code-side) |
|---|---|---|
| Overtrading / fee drag | Gemini 238 trades (secondary); NoFx added code cooldowns after replay | Fixed decision cadence + min-hold + per-symbol cooldown + daily trade cap + require expected move > k x round-trip fee |
| Leverage/liquidation | Claude 20x ETH liquidated (iWeaver) | Spot only on Wallex (no leverage); cap notional per position |
| Unhedged one-way book | Claude 100% long | Max exposure %, max positions, regime filter, forced flat-to-Toman schedule |
| LLM arithmetic / hallucinated prices | NoFx prompt: "NOT formulas"; geometry checks on SL/TP | LLM outputs *intent* (symbol, side, size tier, confidence); code computes qty, SL/TP from ATR and live price; reject if LLM price deviates >x% from mark |
| Malformed/ambiguous output | NoFx `fixMissingQuotes`, `~` range rejection | Strict JSON schema (pydantic) + one retry + fallback to HOLD |
| Stale data | Clodds `maxOrderbookStaleness`; NoFx pruning candidates without market data | Reject decisions if snapshot age > N s; never trade on failed fetch |
| Prompt-only risk | HAA "margin below 70%" not enforced | Every limit enforced in a gate; prompt only mirrors it |
| Whipsaw exits | NoFx 0.5% trigger at 10x "strangled winners" | Price-basis (not margin-basis) stops; min-hold before discretionary close |
| Non-determinism | Flat Circle | temperature 0 (or low), persist plan/invalidation, log raw output, replay from recorded outputs |
| LLM outage | NoFx safe mode after 3 failures | Safe mode: no opens, keep stops/exit-to-Toman |

## Reusable for our system
- **NoFx** (AGPL-3.0: re-implement, do not copy code): (a) `Decision` schema with required SL/TP/confidence/risk and the `parseFullDecisionResponse` -> `validateDecisions` pipeline; (b) `wait` fallback and 3-strike safe mode; (c) "CODE ENFORCED vs AI GUIDED" split printed into the prompt so the LLM knows the gate exists; (d) throttle constants (min hold, cooldown, noise band); (e) 1-minute independent drawdown/profit-giveback monitor (separate goroutine/thread from LLM loop).
- **HAA** (Apache-2.0, safe to port patterns): `max_price/min_price` slippage bounds on LLM orders; trigger-context prompt section ("trigger is NOT an instruction"); `ExecutionSimulator` fee+slippage model; prompt-replay backtest idea (re-ask LLM at stored decision points).
- **CloddsBot** (MIT): `RiskDecision/CheckResult` verdict shape and ordered check pipeline; circuit-breaker config fields.
- **Alpha Arena**: persisted per-position plan with `invalidation_condition`; feeding recent PnL/Sharpe back (NoFx also does, with canned hints; risk: reflexive over-adjustment).

## Recommended design decisions for the hackathon
1. **LLM = decision layer over a deterministic feature + gate pipeline** (strategy logic 40, AI 35, risk 30). The LLM chooses `{action, symbol, size_tier(S/M/L), confidence, thesis, invalidation}` from a compact feature table; code converts to quantities and bracket levels.
2. **Cadence 15 min** (matches NoFx recommendation; 3-day window = ~288 calls, cheap) with an event trigger (volatility/volume spike) allowed to wake earlier but subject to the same cooldowns. Expect active but not hyperactive: target ~5-15 round trips/day total, to keep "activity" points without fee drag.
3. **Gate (outside LLM)**, all enforced: per-position <= 20-25% of equity; max 2-3 open; no all-in; daily loss limit and trailing equity-drawdown halt -> flatten to Toman; min hold + per-symbol cooldown; expected-move >= 3x round-trip fee; SL required; spread/liquidity check from live order book; stale snapshot reject; kill-switch file.
4. **Spot-only semantics**: drop short actions; "close" is the only bearish action; keep final-flat-to-Toman scheduler (hard requirement) before the official end with margin.
5. **Fail-closed**: JSON parse failure or LLM timeout -> HOLD (never retry into a trade); 3 consecutive failures -> safe mode (exits only).
6. Use low temperature and record raw output so judges can replay; include a rule-based fallback labelled as such only for exits, never entries (keeps "real AI use" honest).
7. Show backtest + shadow: reuse HAA-style fee/slippage simulator; record LLM outputs during shadow and replay them in backtest (see file 09).
